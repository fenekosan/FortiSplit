# Инструкция для кодового агента

Ты собираешь и доводишь до рабочего состояния меню-бар приложение macOS
**FortiSplit** (см. README.md — там архитектура и раскладка файлов). Этот
каталог — уже готовый скелет: SwiftPM-проект + bash-скрипты. Твоя задача —
собрать его на этой машине, устранить возможные ошибки компиляции и убедиться,
что базовый сценарий (подключить/отключить/статус/правка маршрутов) работает.

## Контекст и ограничения (не меняй без причины)

- Цель — **личное использование**. Подпись только **ad-hoc** (`codesign -s -`),
  без Apple Developer аккаунта и нотаризации.
- Привилегии — через **sudoers + один root-скрипт** `fortisplit-vpnctl`.
  НЕ переписывай на `SMAppService`/XPC — это потребует Developer ID.
- Split-tunnel держится на `set-routes = 0` в конфиге + маршруты, которые
  кладёт на `pppN` сам `vpnctl` по команде `apply-routes`. Приложение зовёт её,
  когда статус стал CONNECTED, и после правки списка. НЕ включай `set-routes`
  обратно и НЕ возвращай ppp-хуки в `/etc/ppp` — от них ушли сознательно.
- Конфиги живут у пользователя в `~/.config/fortisplit` (`<имя>.config`,
  `<имя>.routes`, `active`) и правятся приложением БЕЗ root. Не переноси их
  обратно в `/etc` — это только добавляло root-команд, ничего не защищая.
- Вне бандла должно оставаться ровно два постоянных файла: `vpnctl` и правило
  sudoers. Ничего больше в систему не клади: скрипт внутри `.app` под NOPASSWD
  нельзя (бандл пишется без пароля), а всё остальное уже вынесено.
- Конфигов может быть несколько; приложение умеет их создавать, импортировать,
  удалять и переключать активный.
- Приложение работает от пользователя и НЕ имеет root; всё привилегированное —
  только через `sudo -n /usr/local/bin/fortisplit-vpnctl <cmd>`.
- Интерфейс двуязычный (en/ru). В коде строки английские, перевод — в
  `Resources/<язык>.lproj/Localizable.strings`; их копирует в бандл
  `build-app.sh`. Новую строку добавляй сразу в оба файла: их совпадение с кодом
  проверяется глазами, автоматической сверки в сборке нет.
- В bash-скриптах перевод — функция `t()` с ключами. Осторожно с массовыми
  заменами по тексту сообщений: правка задевает и строки внутри самой `t()`,
  из-за чего ветка начинает звать саму себя.
- В репозитории НЕТ ничьих личных конфигов: только обезличенный
  `config/example.config` и пустой `config/example.routes`.

## Порядок работы

1. Проверь окружение:
   ```bash
   sw_vers                       # macOS 13+
   swift --version               # есть Command Line Tools
   command -v openfortivpn || echo "нужно: brew install openfortivpn"
   ```
2. Собери приложение:
   ```bash
   ./build-app.sh
   ```
   Если `swift build` ругается — почини ошибки компиляции (см. ниже частые
   места), пока не соберётся `FortiSplit.app`.
3. Проверь запуск бандла: `open ./FortiSplit.app` — в статус-баре должна
   появиться иконка-щит. Если приложение молча не стартует, запусти бинарник
   напрямую и посмотри вывод:
   ```bash
   ./FortiSplit.app/Contents/MacOS/FortiSplit
   ```
4. Установи привилегированные части и проверь sudoers:
   ```bash
   ./install.sh
   sudo -n /usr/local/bin/fortisplit-vpnctl status   # ждём DISCONNECTED
   ```
5. Заполни `~/.config/fortisplit/example.config` (через окно настроек или
   обычным редактором, sudo не нужен) либо импортируй готовый конфиг, затем
   через меню проверь реальное подключение и что маршруты появились:
   `netstat -rn | grep ppp`.

## Критерии готовности

- [ ] `./build-app.sh` собирает `FortiSplit.app` без ошибок, ad-hoc подпись проходит
      (`codesign -dv FortiSplit.app` не ругается).
- [ ] Иконка появляется в статус-баре; меню открывается.
- [ ] `fortisplit-vpnctl status` без пароля возвращает корректный токен
      (`DISCONNECTED` / `CONNECTING` / `CONNECTED\t<ip>`).
- [ ] «Подключить» реально поднимает openfortivpn; «Отключить» — гасит.
- [ ] Окно настроек: список конфигов, переключение активного, импорт файла с
      диска, создание и удаление работают.
- [ ] Вкладка «Маршруты» читает и сохраняет `<имя>.routes`; при активном
      туннеле «Сохранить и применить» добавляет новые подсети на pppN.
- [ ] После подключения маршруты появляются сами (приложение зовёт
      `apply-routes` на переходе статуса в CONNECTED).
- [ ] На отключении маршруты снимаются, дефолт остаётся системным (проверь, что
      обычный трафик НЕ идёт в туннель: `route -n get 8.8.8.8` → не ppp).

## Частые места, где может понадобиться правка

- **SwiftUI concurrency**: код написан на классическом
  `DispatchQueue`-паттерне без строгой изоляции акторов. Если включишь Swift 6
  strict concurrency, появятся предупреждения об `@Published` из фонового
  потока — все мутации `@Published` уже завёрнуты в `DispatchQueue.main.async`,
  но проверь. Достаточно `-swift-version 5`.
- **`MenuBarExtra` + `openWindow`**: окно настроек открывается по `id: "settings"`.
  Если окно не выходит на передний план — оставлен `NSApp.activate(...)`.
- **Определение ppp-интерфейса**: `fortisplit-vpnctl` берёт первый `pppN`
  (не хардкодит ppp0), т.к. номер может отличаться. Если у пользователя есть
  другие PPP-подключения, уточни фильтр.
- **Маршруты не появились**: проверь, что `set-routes = 0` реально в конфиге, и
  позови команду руками —
  `sudo -n fortisplit-vpnctl apply-routes ~/.config/fortisplit/<имя>.routes`.
  Она печатает, сколько подсетей легло и на какой интерфейс, а негодные строки
  выводит в stderr.
- **Иконки статус-бара** собираются из `Resources/AppIcon.png` скриптом
  `swift scripts/make-menubar-icon.swift`: эмблема минус расширенная труба даёт
  залитый щит с прорезью, плюс контурная версия. Это работает только потому,
  что в исходнике плоский фон и плоские заливки. На картинке с градиентом и
  свечением (первая версия иконки) тот же приём давал нечитаемое пятно, а
  заливка внутренности щита от центра утекала на фон через разрывы в контуре.
  Если картинку опять сменят на «объёмную» — проверь предпросмотром
  (`--preview <каталог>`) прежде чем верить результату.
- **Толщина обводки**: на 18 точках штрих тоньше пикселя выцветает в серую
  кашу. Радиус эрозии подобран так, чтобы выходило около двух точек.
- **Иконка приложения**: `Resources/AppIcon.png` (1024×1024) ->
  `./scripts/make-icns.sh` -> `Resources/FortiSplit.icns`, дальше её копирует
  `build-app.sh`. В `Info.plist` за это отвечает `CFBundleIconFile`.

## Раздача

Артефакт релиза — `dist/FortiSplit-<версия>.pkg`, собирается
`./scripts/make-pkg.sh`. Правило sudoers пишет `postinstall`: пользователя он
берёт как `stat -f%Su /dev/console`, потому что сам работает от root. Не забудь
`pkgbuild --ownership recommended` — иначе root-скрипт приедет с правами
сборщика, и sudoers будет доверять файлу, который пользователь может переписать.
Пакет неподписанный (нужен Developer ID Installer), поэтому в README расписано,
как разрешить запуск через системные настройки.

## Пути развития (не для этой итерации)

- Автозапуск/reconnect: `LaunchAgent` пользователя, который держит приложение,
  или демонизация самого openfortivpn.
- Счётчик трафика/времени в меню (парсинг `ifconfig pppN` и лога).
- Строгая модель безопасности: `SMAppService` + XPC + Developer ID + нотаризация
  (тогда `.app` самодостаточен, но нужен платный аккаунт — вне текущей задачи).
